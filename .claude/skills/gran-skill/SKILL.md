# GRAN (Graph Recurrent Attention Networks) Skill

## Overview

GRAN is a graph generation model from NeurIPS 2019 that generates graphs efficiently via an autoregressive process. Instead of generating one edge at a time (like GraphRNN), GRAN generates a **block of nodes and their edges** at each step using a GNN with attention-based message passing. Edges are modeled as a **mixture of Bernoulli** distributions.

**Paper**: [Efficient Graph Generation with Graph Recurrent Attention Networks](https://arxiv.org/abs/1910.00760)

## Architecture

### Core Model: `GRANMixtureBernoulli`

The model generates adjacency matrices row-by-row in blocks:

```
[Existing graph (adj rows 0..t)] --> GNN propagation --> Predict edges for new block of K nodes
```

**Components**:

1. **GNN Decoder** (`model/gran_mixture_bernoulli.py:GNN`):
   - Multi-layer GRUCell-based message passing
   - Optional attention on messages (sigmoid gating)
   - Message = MLP(state_diff || edge_feat), gated by attention
   - Aggregation by scatter_add, update via GRUCell

2. **Edge Prediction Head**:
   - `output_theta`: MLP -> logits for each Bernoulli component (E x D)
   - `output_alpha`: MLP -> mixture weights (E x D)
   - Loss: `mixture_bernoulli_loss` with logsumexp over components and canonical orderings

3. **Symmetry-Breaking Edge Features**:
   - One-hot encoding (`att_edge_dim=64` per direction, total 128) distinguishing existing vs. new nodes
   - New nodes get positional indices 1..K, existing nodes get 0

## Data Pipeline

### `GRANData` (`dataset/gran_data.py`)

The dataset preprocesses each graph into multiple **canonical orderings** of the adjacency matrix (DFS, BFS, k-core, degree-descent, etc.), then for each ordering extracts subgraphs for autoregressive training:

1. **Node ordering**: Reorder adjacency matrix by DFS/BFS/k-core/degree
2. **Subgraph extraction**: For each position `jj` in [0, N, stride], extract the subgraph of first `jj+K` nodes
3. **Edge construction**: Build edges for GNN propagation (fully connected for new block)
4. **Label extraction**: Ground-truth edges for the new block rows
5. **Attention index**: Mark new nodes with positional indices 1..K

Key data dict keys returned per sample:
- `adj`: (C, N, N) - canonical orderings of lower-triangular adjacency
- `edges`: (E, 2) - GNN propagation edges (sparse)
- `node_idx_gnn`: (M, 2) - pairs for edge prediction
- `node_idx_feat`: (N,) - feature index (inf for new nodes)
- `att_idx`: (N,) - attention positional encoding
- `label`: (M,) - binary edge labels
- `subgraph_idx`: (M,) - subgraph membership

## Key Implementation Details

- **Config system**: YAML configs loaded via `utils/arg_helper.py` into `easydict.EasyDict` for dot-access
- **Runner pattern**: `GranRunner` handles train/test lifecycle, TensorBoard logging, model snapshots
- **Custom DataParallel**: `utils/data_parallel.py` wraps `nn.DataParallel` to handle dict inputs across GPUs
- **Subgraph batching**: Each training sample produces multiple subgraph-level forward passes (`num_fwd_pass`), with `num_subgraph_batch` controlling how many subgraphs per sample
- **Canonical orderings**: Multiple node orderings (DFS, BFS, k-core, degree) serve as data augmentation; the loss marginalizes over orderings via logsumexp
- **No edge features in generation**: During sampling, adjacency is built incrementally; edge features are purely the attention one-hot encoding

## Relationship to GSDiff

GRAN is a **baseline/prior work** for graph generation. GSDiff improves upon autoregressive methods like GRAN by using diffusion-based generation, which allows parallel generation of all nodes/edges rather than sequential autoregressive decoding. Key differences:

| Aspect | GRAN | GSDiff |
|--------|------|--------|
| Generation | Autoregressive (row-by-row) | Diffusion (parallel denoising) |
| Output | Adjacency matrix only | Coordinates + semantics + edges |
| Domain | Generic graphs | Vector floorplans |
| Conditioning | None | Topology / boundary |
| Node features | None (structure only) | 2D coords + 7 room types |
