# GSDiff OpenCode Skill

Official implementation of the AAAI 2025 paper: **"GSDiff: Synthesizing Vector Floorplans via Geometry-enhanced Structural Graph Generation"**

## Overview

GSDiff is a diffusion-based generative model that synthesizes **vector floorplans** as structural graphs. Unlike raster-based approaches, GSDiff generates floorplans as graphs where nodes represent room corners (with coordinates and semantic attributes) and edges represent walls/adjacency relationships.

### Key Contributions
- **Two-stage generation pipeline**: Stage 1 generates nodes (room corners) via a denoising diffusion Transformer; Stage 2 predicts edges (walls) via a separate Transformer with a random self-supervision strategy
- **Geometry-enhanced structural graph representation**: Rooms are represented as graph cycles with semantic labels, corners carry coordinate + room-type attributes
- **Three constraint modes**: Unconstrained, topology-constrained (from bubble diagrams), and boundary-constrained (from boundary images)
- **Supports two datasets**: RPLAN (80,788 floorplans) and LIFULL HOME'S (10,804 floorplans)

## Architecture Details

### Stage 1: Node Generation (Denoising Diffusion Transformer)

- **Model**: `house_nn1.py` -> `HeterHouseModel`
- **Input**: Padded node features `(batch, 53, 9)` — 2 coordinates + 7 simplified room-type semantics
- **Architecture**: Multi-head attention Transformer with InstanceNorm, Pre-Norm residual connections
- **Attention masking**: Global attention matrix from padding masks to handle variable-length graphs
- **Diffusion**: 1000 timesteps, cosine beta schedule
- **Output**: Denoised node coordinates and semantic attributes

### Stage 2: Edge Prediction (Transformer with Random Self-Supervision)

- **Model**: `house_nn2.py` -> `EdgeModel`
- **Input**: Generated node features from Stage 1
- **Innovation**: Random self-supervision strategy during training — randomly masks edges and trains the model to reconstruct them
- **Output**: Edge adjacency matrix `(N*N, 2)` — binary wall/no-wall predictions

### Constraint Encoders

- **Boundary CNN** (`boundary_78_10.py`): Encodes boundary images into latent representations for boundary-constrained generation
- **Topology Transformer** (`bubble_diagram_57_9.py`): Encodes bubble diagrams (room adjacency graphs) into latent representations for topology-constrained generation

### Data Representation

- **Nodes**: Each corner has `(x, y, sem_0, sem_1, ..., sem_6)` — 9-dim features
- **Room semantics** (7 simplified categories): Living room, Bedroom, Bathroom, Kitchen, Balcony, Storage, External wall
- **Edges**: Flattened adjacency matrix `(N^2, 2)` — one-hot [connected, not-connected]
- **Padding**: All graphs padded to max 53 nodes with attention masking
- **Normalization**: Coordinates normalized to [0, 1] range

## Key Concepts

### Diffusion Process
- **Forward**: Gradually adds Gaussian noise over 1000 timesteps using cosine beta schedule
- **Reverse**: Transformer predicts noise at each step; uses posterior mean formula for denoising
- **Clamp trick**: During training, clamps predicted x_0 to valid coordinate range for stability

### Graph-to-Floorplan Rendering
1. Predicted nodes give corner coordinates + room semantics
2. Predicted edges give wall connectivity
3. `networkx` cycle detection finds room polygons from the graph
4. Rooms are filled with semantic colors and rendered as 256x256 images
5. Rendered images are used for FID/KID evaluation against ground truth

### Room Semantic Categories (Simplified)
| Index | Category |
|-------|----------|
| 0 | Living Room / Dining Room / Function Room |
| 1 | Bedroom / Study / Second Bedroom / Children's Room / Guest Room |
| 2 | Bathroom / Toilet |
| 3 | Kitchen |
| 4 | Balcony |
| 5 | Storage |
| 6 | External Wall |

### Evaluation Metrics
- **FID** (Frechet Inception Distance): Measures distribution similarity between generated and real floorplan images
- **KID** (Kernel Inception Distance): Similar to FID but with unbiased estimator
- **GED** (Graph Edit Distance): Measures structural similarity between generated and target topology graphs
- **Geometry metrics**: Room area distribution, aspect ratio, alignment quality
- **Topological metrics**: Room count per type, adjacency accuracy

## Troubleshooting

### Common Issues

1. **`sys.path` errors**: Update all hardcoded paths in scripts to your local installation
2. **CUDA OOM**: Reduce `batch_size` (train) or `batch_size_test` (inference)
3. **Missing data files**: Ensure RPLAN preprocessing pipeline completed all steps (check for `rplang-v3-withsemantics/` directory with 71,763 files)
4. **Different topology results**: Bubble diagram GT semantics involve randomness; minor differences from paper results are expected at scale
5. **Alternative semantic extraction**: Use `get_cycle_basis_and_semantic_3_semansimplified` instead of `get_cycle_basis_and_semantic_2_semansimplified` in `rplan-process8/9/10.py` for deterministic (non-random) room semantics

### Device Configuration
All scripts default to `cuda:0`. Change the `device` variable in each script to match your setup.
