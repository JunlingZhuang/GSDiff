# 关键决策阈值速查

> Healthcare Floor Plan Agent 开发计划（拆分版）｜ [← 总览与文档地图](README.md)

| 决策点 | 阈值/规则 | 来源 |
|--------|-----------|------|
| VLM 直出坐标？ | 否，两阶段（结构/几何分离） | 门窗精度仅 0.09-0.39 |
| 切 Plan B（扩散refine）？ | VLM几何合法率 fail > 30% | Phase 0-A 测 |
| 门窗怎么来？ | 规则推断为主(策略C)，非图像检测 | 门窗精度仅0.09-0.39 |
| 门窗怎么存？ | 挂墙(wall_id+相对位置)，非独立坐标 | 关系式建模 |
| LLM 自评纠错？ | 绝不，外部验证器驱动 | GPT-4 自纠 95.5%→89.0% |
| 纠错迭代上限 | 3-5 轮，写 typed state | 工程案例47轮烧$180 |
| 触顶怎么办 | 返回违规最少版 + 转人工 | 收敛工程 |
| 违规不降 | 立即转人工，别烧token | — |
| Reviewer 改动范围 | 强制单元素局部，禁整体重写 | Text2BIM 失败模式 |
| 硬规范判定 | 确定性规则引擎，非LLM | Chen & Bao |
| 软导则 | RAG + 典型知识图 | COLING 2025 |
| 退回点决策 | LLM诊断+人确认，计数器兜底 | 混合最稳 |
| Supervisor递归上限 | ~25（4专家），触顶=loop bug | LangGraph |
| 后期加更多agent？ | 瓶颈触发，非默认；大多数增强用确定性节点 | 别为高级而拆 |
| 加agent vs 加节点 | 语义/并行/隔离→agent；校验/红线→确定性节点 | 核心哲学 |
| 模型分档 | Supervisor前沿+worker便宜，省~60% | 工程实践 |
| 交互入口 | 聊天+按钮+拖拽，共用统一op入口 | 后端不区分来源 |
| 操作走agent？ | 明确操作走按钮(快)，模糊意图走聊天 | 不滥用agent |
| API形态 | 单流式API(SSE/WS)，事件类型化分流 | chat+canvas双输出 |
| reasoning给用户 | 精炼进度版，机器细节走LangSmith | 分层 |
| 前端渲染库 | react-konva(MIT免费)，避开tldraw(收费+水印+回传) | healthcare合规 |
| 前端要WASM？ | 否，量级不够+重算在后端 | 过早优化 |
| AI写前端哪部分 | 业务层(吸附/同步/UI)，非canvas底层 | 别重造Konva |
| checkpointer | 生产用PostgresSaver，非InMemory | — |
| 前后端连接 | 不验证，直接做（不确定性≈0） | 风险分级 |
| 验证投入原则 | ∝ 不确定性，不 ∝ 重要性 | — |
