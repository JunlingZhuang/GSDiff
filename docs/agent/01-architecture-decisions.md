# 核心架构决策

> Healthcare Floor Plan Agent 开发计划（拆分版）｜ [← 总览与文档地图](README.md)

> 这些决策已在调研中得到论文与工程证据支撑，是不可动摇的地基。

### 2.1 LangGraph 状态机做主体，不用全自主 ReAct

**理由**：系统有固定管线 + 合规红线 + 退回/审计需求。这五条全压向状态机：固定管线、合规红线、中途反悔/退回、审计可追溯、并行汇总。全自主 ReAct 守不住合规红线（不保证每次跑确定性校验）和退回（状态混在对话流里无干净边界）。

### 2.2 生成环节做成内嵌的 DeepAgents 子图

**理由**：生成 healthcare 平面需要动态 planning + 多步试错（这是 DeepAgents 封装好的能力），但合规与管线必须由外层状态机守住。形态 = **外层 LangGraph 骨架包着一个受约束的生成子图**。子图 = 一张编译好的图被当节点用（图里套图）；DeepAgents 编译出的就是 CompiledStateGraph，能无缝嵌入。

### 2.3 两阶段生成：LLM 出结构，确定性出几何

**理由（强证据）**：VLM 提取门窗符号精确匹配率仅 0.09–0.39（误差 20–50%），房间计数可达 0.74–0.91。**别让 Gemini 直出精确坐标**。HouseTune（AAAI 2026）、HouseLLM、ChatHouseDiffusion 一致验证"LLM 出粗布局 → 专门 refine 出几何"，兼容性提升 79%。

### 2.4 纠错循环必须由外部确定性验证器驱动

**理由（最反直觉但最确定）**：LLM 自我纠错有害——GPT-4 在 GSM8K 上自纠一轮 95.5%→91.5%，两轮→89.0%。但用外部可靠反馈纠错有效（CRITIC, LLM-Modulo）。**绝不能让 LLM 当自己的裁判**，每次改完重跑确定性校验。

### 2.5 硬规范 vs 软导则架构上分离

| | 硬规范 | 软导则 |
|---|--------|--------|
| 例 | 疏散门宽、净距、必备房间 | 洁污分流、朝向、动线 |
| 存储 | 结构化为可执行规则（规则引擎） | 向量化 + 典型知识图（RAG） |
| 判定 | 确定性代码，pass/fail | LLM 评审，主观评分 |
| 修复 | 求解器算最小几何修复 | LLM 建议 |

### 2.6 一个后端，不是多个

数据模型、agent、CV、规范引擎全在**同一个 FastAPI 进程**内。数据模型是其中的地基层（几个文件），不是独立服务。仅当某组件（如 GPU 跑 VLM）后期成为性能瓶颈时，才考虑拆为微服务——且拆的是重计算组件，绝不拆数据模型。
