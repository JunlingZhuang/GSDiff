# 准确度优化方法

> Healthcare Floor Plan Agent 开发计划（拆分版）｜ [← 总览与文档地图](README.md)

> 来自论文调研的可执行优化手段，按管线环节组织。

### 11.1 生成环节

- **两阶段生成**：Gemini 出结构/拓扑，几何交确定性 refine（HouseTune/HouseLLM，兼容性+79%）。
- **典型库注入**（MedBuild AI "knowledge-injected generation"）：给生成 prompt 注入 healthcare typology 库（验证过的医院原型）+ 科室邻接规则（HSLP 活动关系图），约束解空间。
- **领域 CoT 模板**（HouseTune 消融）：预定义领域 CoT > 通用"think step by step"。
- **让 Gemini 同时出 bubble diagram/邻接图 + JSON 多边形**（DStruct2Design 格式），不只出图。

### 11.2 CV parse 环节

- **junctions → IP 装配 → Shapely 规整**（Raster-to-Vector，~90% 精度）：检测墙交点，整数规划装配成闭合多边形（保证拓扑合法），Shapely 收尾（正交规整、buffer(0) 修自相交、删碎多边形、统一墙厚）。
- **Manhattan 正交矫正**：建筑平面几乎正交，强制拉正消除模型生成的歪斜。
- **VLM-as-judge 图像预检**（CVPR 2025）：parse 前用外部 CV + 视觉标记验证图像匹配规格，不让 VLM 自评。

#### 11.2.1 门窗检测策略（CV parse 最薄弱环节，单独处理）

> **根本现实**：色块图擅长表达房间（颜色填充易分割），但不擅长表达门窗（墙上小开口/符号，跨图纸不稳定）。门窗精确匹配率仅 0.09–0.39（房间计数可达 0.74–0.91）。**不能指望从色块图直接 parse 出准确门窗。** 这是路线固有局限，必须正面处理。

**三种来源策略（按可靠性递增）：**

```
策略A：从图像检测门窗     ← 最直觉，但最不可靠，仅作辅助
策略B：门窗专门检测器     ← CV 检测，中等可靠，作校正
策略C：规则/agent 推断    ← 不依赖图像，最可靠 ★推荐主力
```

| 策略 | 方法 | 可靠性 | 定位 |
|------|------|--------|------|
| A 图像检测 | VLM 用特定标记画门窗，CV 检测标记 | 低（0.09-0.39） | 仅辅助信号，非真相源 |
| B 专门检测器 | Co-DETR 门检测器（门符号跨图纸稳定）/ CubiCasa junction heatmap | 中 | 校正信号 |
| C 规则推断 | 按房间邻接关系 + healthcare 规范推断门窗 | 高 | **主力** |

**为什么策略 C 对 healthcare 最优**：医院的门不是随便开的，由功能和规范决定——病房必须通走廊、手术室门要够宽、洁污分区门有讲究。这些是**规则**，比从模糊图像里猜准一个量级。

**策略 C 推断逻辑**：

```
逻辑：两个相邻房间之间，共享墙上应有门（否则不连通）
   │
   ▼
parse 出房间多边形和邻接图后：
   ├─ 病房 r1 与 走廊 corridor_1 相邻 → 共享墙上需一道门
   ├─ 门位置：共享墙中点（或按动线/规范优化）
   └─ 门宽：按 healthcare 规范取（病房门 ≥1100mm 等）
窗：外墙房间按采光/通风规范推断（病房必须采光等）
```

**关键：门窗"落墙"而非存独立坐标**（呼应数据模型关系式建模）：

```
检测/推断到一个门
   │
   ▼
① 找最近的墙 wall_id
② 计算门在该墙的相对位置 (0~1)
③ 取门宽（规范决定）
   │
   ▼
存成 {"id":"d1","wall_id":"w1","position":0.5,"width":1200}
     而非 {"door":[[x1,y1],[x2,y2]]}
→ 墙移动门自动跟随，不飘空
```

**推荐混合方案（C 为主、B 为辅、A 基本放弃）**：

```
1. 主力：邻接图 + 规范推断门窗（策略C）
2. 辅助：若图像有清晰门符号，用 Co-DETR 检测校正（策略B）
   - 检测结果与规则推断对比，不一致时以规范为准
3. 窗：外墙房间按采光规范推断（healthcare 有明确采光/通风要求）
```

> **风险提示**：门窗检测正落在 Phase 0-A 命门验证内（CV parse 精度最低部分）。若试图走策略 A，Phase 0-A 大概率暴露"门窗 parse 不可用"，这恰会推动转向策略 C。再次印证核心哲学：**门窗的精确性不靠 VLM/CV 从模糊图像猜，而靠确定性规则 + 规范来定。**

### 11.3 纠错环节

- **结构化量化反馈**：带元素 ID + 精确规则阈值。
- **最小几何修复**（neuro-symbolic SMT，arXiv 2601.06181）：违规时求解器算最小改动恢复合规，而非让 LLM 猜。
- **批量改 + Reflexion 记忆 + 硬上限 + 返回最优版**。

### 11.4 规范环节

- **三层 RAG + 事件图**（COLING 2025）：静态层（事实）+ 动态层（规范用事件图建模）+ 计算层。
- **典型知识图**（ComplianceNLP，90.7% 精度）：用类型化知识图而非纯向量检索。
- **多阶段校验**（SYNAPSE）：句法→语义合理范围→规范限值。

### 11.5 阈值触发的方案切换

**若 VLM 坐标几何合法率 fail > ~30%** → 从"信任 VLM 几何"切到"LLM 出邻接图 → 确定性求解器摆几何"（FlairGPT 模式）。这是 Phase 0-A 要测的数。
