# 风险分级与验证策略

> Healthcare Floor Plan Agent 开发计划（拆分版）｜ [← 总览与文档地图](README.md)

> **核心原则：验证投入 ∝ 不确定性，不 ∝ 重要性。**

### 7.1 风险分级

```
🔴 高风险（必须独立验证，可能决定项目成败）
   ① VLM 色块图生成 + CV parse 精度 —— 生成路线命门
   ② agent 编排质量 —— 循环能否收敛、planning、退回判断

🟡 中风险（需设计，大概率能做成）
   ③ 规范引擎（建筑规范→可执行规则）—— 工作量大但确定能做
   ④ 数据模型 —— 要想清楚但确定能做

🟢 低风险（已知能做，直接实现，不验证）
   ⑤ 前后端连接 / WebSocket / API
   ⑥ 鉴权 / 限流 / 数据库 / 部署
   ⑦ 前端画布渲染
```

**前后端连接不确定性≈0 → 不验证，直接做。** 验证精力只投 🔴。

### 7.2 两个独立命门要分开验证（可并行）

```
Phase 0（两个并行验证轨，互不依赖）
│
├── 0-A: 验证生成路线 🔴
│       generate_colorblock → cv_parse → render_plan 三个正式 tool + 单测
│       先 round-trip 闭环(合成Plan→渲染→parse→对比)把 parser 测到可信，
│       再真调 Gemini 量 VLM 图像质量 —— 两个变量干净分离
│       产出：路线走不走得通的结论 + 沉淀为生产管线节点的 tool/测试
│       (tool 级带 I/O 契约，不碰编排、不碰前后端 —— 详见 §8.3 Phase 0 修订)
│
└── 0-B: 验证 agent 编排 🔴
        mock掉VLM/CV → 喂故意带违规的假平面 → 跑生成校验纠错循环
        看：能否收敛、planning合理性、退回判断准否
        产出：编排可行性 + prompt/循环设计
        (用 mock，不碰真VLM/CV、不碰前后端)
```

### 7.3 agent 编排用 mock 隔离验证

验证编排时把 VLM 和 CV 换成 mock，出问题就知道是编排逻辑，不被 VLM/CV 噪声干扰。喂一个"故意 X 处违规"的假平面，看纠错循环能否 N 轮内修到合规、会否死循环、退回判断对否。KirtiJha 模板自带零配置 mock 模型，正好用来做这种隔离验证。
